01 / THE CHALLENGE

Overview

Objective

Develop a cloud-connected IoT system using an ESP32, MQTT, and Adafruit IO so a user can control an LED remotely from a web dashboard.

Problem being addressed

Task 1 controlled the LED through a webpage hosted directly on the ESP32. That direct connection normally requires the browser device and ESP32 to be on the same local network. This task adds cloud messaging so the command can travel through the internet.

Project summary

The ESP32 connects to the internet and authenticates with the Adafruit IO MQTT broker. A dashboard control publishes an ON or OFF value to the bulb-control feed. The ESP32 subscribes to that feed, receives the message, and sets GPIO 2 to control the LED.

02 / THE COMMUNICATION MODEL

Dashboard, broker, device

The Adafruit IO dashboard is the publisher when the user changes the LED control. It sends the selected ON or OFF value.

02 / BROKER

Adafruit IO

The broker accepts published messages and forwards them to connected clients subscribed to the matching feed.

03 / CHANNEL

Feed / topic

A named data channel. Adafruit IO exposes feeds as MQTT topics for sending and receiving values.

04 / SUBSCRIBER

ESP32

The ESP32 subscriber listens for feed updates and changes the LED output when a command arrives.

MQTT FEED / TOPICKixorr_28/feeds/bulb-control

This is the account-specific feed path. The AIO Key is used for authentication and must remain private.

Why MQTT?

MQTT (Message Queuing Telemetry Transport) is a lightweight messaging protocol commonly used in IoT. Its publish/subscribe model separates the dashboard from the hardware: the dashboard publishes to a feed, while the ESP32 subscribes to it. Adafruit IO's broker routes the message between them.

03 / END-TO-END OPERATION

System design & data flow

The full system contains the user, Adafruit IO dashboard, MQTT broker/feed, ESP32 subscriber, and GPIO-controlled LED.

  1. The ESP32 joins a Wi-Fi network with internet access.
  2. The ESP32 connects and authenticates with the Adafruit IO MQTT broker.
  3. The device subscribes to Kixorr_28/feeds/bulb-control.
  4. The user opens the Adafruit IO dashboard and selects the LED control.
  5. The dashboard publishes the selected ON or OFF value to the feed.
  6. The broker receives the value and forwards it to the subscribed ESP32.
  7. The ESP32 reads the message and updates the LED GPIO output.

05 / FIRMWARE

ESP32 MQTT subscriber

Join Wi-FiConnect brokerSubscribe to feedUpdate GPIO

Install the ESP32 board package and Adafruit MQTT library in Arduino IDE. Replace the placeholders privately before uploading.

ESP32_Adafruit_IO_MQTT.ino
#include <WiFi.h>
#include "Adafruit_MQTT.h"
#include "Adafruit_MQTT_Client.h"

#define WIFI_SSID "YOUR_WIFI_NAME"
#define WIFI_PASSWORD "YOUR_WIFI_PASSWORD"
#define AIO_SERVER "io.adafruit.com"
#define AIO_SERVERPORT 1883
#define AIO_USERNAME "Kixorr_28"
#define AIO_KEY "YOUR_ADAFRUIT_IO_KEY"
#define LED_PIN 2

WiFiClient client;
Adafruit_MQTT_Client mqtt(
  &client, AIO_SERVER, AIO_SERVERPORT, AIO_USERNAME, AIO_KEY);

Adafruit_MQTT_Subscribe bulbControl = Adafruit_MQTT_Subscribe(
  &mqtt, AIO_USERNAME "/feeds/bulb-control");

void setup() {
  Serial.begin(115200);
  pinMode(LED_PIN, OUTPUT);
  digitalWrite(LED_PIN, LOW);

  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);
  Serial.print("Connecting to Wi-Fi");
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }
    Serial.println();
    Serial.println("Wi-Fi connected");
  Serial.print("IP Address: ");
  Serial.println(WiFi.localIP());

  mqtt.subscribe(&bulbControl);
}

void connectMQTT() {
  int8_t result;
  if (mqtt.connected()) return;

  Serial.print("Connecting to Adafruit IO...");
  while ((result = mqtt.connect()) != 0) {
    Serial.println(mqtt.connectErrorString(result));
    mqtt.disconnect();
    delay(5000);
  }
  Serial.println("Connected to Adafruit IO");
}

void loop() {
  connectMQTT();
  mqtt.processPackets(1000);

  Adafruit_MQTT_Subscribe *subscription;
  while ((subscription = mqtt.readSubscription(1000))) {
    if (subscription == &bulbControl) {
      String command = (char *)bulbControl.lastread;
      command.trim();
      Serial.print("Received: ");
      Serial.println(command);

      if (command == "ON") {
        digitalWrite(LED_PIN, HIGH);
        Serial.println("LED ON");
      } else if (command == "OFF") {
        digitalWrite(LED_PIN, LOW);
        Serial.println("LED OFF");
      }
    }
  }
}

Important code sections

  • WiFi.begin() starts the ESP32 Wi-Fi connection; the board needs internet access to reach the cloud broker.
  • The broker host, port, account username, and AIO Key configure the MQTT client.
  • Adafruit_MQTT_Subscribe binds the client to Kixorr_28/feeds/bulb-control.
  • mqtt.connect() authenticates with Adafruit IO. If it fails, the sketch reports the error, disconnects, waits, and retries.
  • mqtt.processPackets() and mqtt.readSubscription() process incoming messages.
  • The received payload is trimmed and compared with ON/OFF before GPIO 2 is updated.

07 / DEBUG NOTES

Challenges & fixes

MQTT connection failed

Check Wi-Fi internet access, broker address, port, Adafruit IO username, and AIO Key.

Connected, but no LED command arrives

Verify that the feed is named bulb-control and the full subscription path is Kixorr_28/feeds/bulb-control.

Authentication was rejected

Re-enter the correct Adafruit IO username and AIO Key. Keep the key private.

Message arrives but LED does not change

Use Serial Monitor to inspect the received value, and check the LED GPIO pin and wiring.

Local Task 1 worked, but remote control does not

This task requires an internet-connected Wi-Fi network so the ESP32 can reach Adafruit IO.

Compared with the local web-server approach in Task 1, cloud messaging makes remote control possible wherever the device has internet access.
