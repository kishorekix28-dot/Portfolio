01 / THE CHALLENGE

Overview

Objective

Develop a simple IoT system using an ESP32 that hosts a web server and lets a user control an LED through a browser over Wi-Fi.

Problem being addressed

An LED is usually controlled with a physical switch or pre-programmed logic. This project demonstrates remote control through a web interface, without a physical switch.

Project summary

The ESP32 joins a Wi-Fi network and serves an HTML page. ON and OFF controls send HTTP requests that change the LED's GPIO state.

HTTP request

The URL path identifies whether the user requested LED ON or LED OFF.

04

HTML interface

Two browser controls send the corresponding request to the ESP32.

Data flow

  1. ESP32 connects to Wi-Fi and starts its web server.
  2. The IP address is read from the Arduino Serial Monitor.
  3. The user opens that address in a browser on the same network.
  4. ESP32 serves the LED control page.
  5. A button click sends /LED=ON or /LED=OFF.
  6. The ESP32 updates GPIO 2 and returns the page.

04 / FIRMWARE

Implementation

Set Wi-Fi credentials Initialize GPIO Start server Handle request

The sketch below is formatted from the supplied implementation. Replace the Wi-Fi placeholders locally before uploading; never publish real credentials.

ESP32_Web_Server.ino
#include <WiFi.h>

const char* ssid = "YOUR_WIFI_NAME";
const char* password = "YOUR_WIFI_PASSWORD";
WiFiServer server(80);
const int ledPin = 2;

void setup() {
  Serial.begin(115200);
  pinMode(ledPin, OUTPUT);
  digitalWrite(ledPin, LOW);

  WiFi.begin(ssid, password);
  Serial.print("Connecting to Wi-Fi");
  while (WiFi.status() != WL_CONNECTED) {
    delay(500);
    Serial.print(".");
  }

    Serial.println("\nWi-Fi connected");
  Serial.print("ESP32 IP Address: ");
  Serial.println(WiFi.localIP());
  server.begin();
}

void loop() {
  WiFiClient client = server.available();
  if (!client) return;

    String request = client.readStringUntil('\r');
  client.flush();

  if (request.indexOf("GET /LED=ON") >= 0) {
    digitalWrite(ledPin, HIGH);
  }
  if (request.indexOf("GET /LED=OFF") >= 0) {
    digitalWrite(ledPin, LOW);
  }

  client.println("HTTP/1.1 200 OK");
  client.println("Content-Type: text/html");
  client.println("Connection: close");
  client.println();
  client.println("<!DOCTYPE html><html><head>");
  client.println("<meta name='viewport' content='width=device-width, initial-scale=1'>");
  client.println("<title>ESP32 LED Control</title></head><body>");
  client.println("<h1>ESP32 LED Control</h1>");
  client.println("<p><a href='/LED=ON'><button>LED ON</button></a></p>");
  client.println("<p><a href='/LED=OFF'><button>LED OFF</button></a></p>");
  client.println("</body></html>");
  delay(1);
  client.stop();
}

What the key parts do

  • WiFi.begin() joins the configured wireless network.
  • WiFiServer server(80) listens on the standard HTTP port.
  • The request path selects HIGH or LOW for the LED GPIO.
  • The response returns a small HTML page with ON and OFF links.

06 / DEBUG NOTES

Challenges & fixes

ESP32 could not connect to Wi-Fi

Recheck the SSID and password, then ensure the board is within network range.

Webpage could not be opened

Use the current IP printed in Serial Monitor and connect the browser device to the same Wi-Fi network.

LED did not respond

Check the GPIO pin configuration, LED polarity, resistor wiring, and request paths.

IP address changed after reconnecting

Read the current IP from Serial Monitor each time the ESP32 joins the network.
